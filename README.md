# StudentProject

ASP.NET Core REST API для управления событиями.

## Требования
1. На компьютеры должны быть установлены Docker Desktop и .NET SDK 9+

## Сборка и остановка
1. Для сборки из корня проекта в терминале выполнить
   `
   docker compose up --build
   `
   При первом запуске контейнеры автоматически применяют миграции EF Core при старте сервисов.
3. Для остановки из корня проекта в терминале выполнить
   `
   docker compose down
   `

## Состав системы

Решение состоит из 3 сервисов, которые взаимодействуют через Apache Kafka:

- **Users Service**
  - Регистрация пользователя
  - Аутентификация пользователя
    
- **Events Service**
  - Создание событий
  - Обновление событий
  - Удаление событий
  - Бронирование мест на событие как consumer

- **Bookings Service**
  - Создание брони на событие как producer
  - Отмена брони
  - Удаление брони

В решение также добавлен общий контракт работы с сообщениями из Kafka. 
Имя топика для отслеживания `booking-confirmed`

### Пример создания брони
1. Пользователь создает бронь через Bookings
2. Бронь добавляется в БД `bookings_db`
3. Публикуется событие `booking-confirmed` в Kafka
4. Events подписан на событие и уменьшает кол-во доступных мест

## Состав сервиса
Сервис разбит на 4 слоя. 
Domain => Application => Infrastructure => Presentation

### Состав каждого слоя проекта:
- Domain — доменные сущности, value objects, доменные исключения. Не зависит ни от чего внешнего.
- Application — use cases, сервисы, интерфейсы портов (репозитории, шлюзы), DTO. Зависит только от Domain.
- Infrastructure — реализации портов: репозитории, DbContext, внешние клиенты. Зависит от Application и Domain.
- Presentation — контроллеры/Minimal API эндпоинты, HTTP-маппинг, регистрация зависимостей. Зависит от Application и Infrastructure.

### Каждый сервис использует свою БД
- `users_db`
- `events_db`
- `bookings_db`

## Модель Booking (бронь)
Состав полей:
- UserId (Guid, обязательное) — уникальный идентификатор пользователя;
- Id (Guid, обязательное) — уникальный идентификатор брони;
- EventId (Guid, обязательное) — идентификатор события, к которому относится бронь;
- Status (BookingStatus, обязательное) — текущий статус брони:
  - Pending — бронь создана, ожидает обработки;
  - Confirmed — бронь подтверждена;
  - Rejected — бронь отклонена.
- CreatedAt (DateTime, обязательное) — дата и время создания брони;
- ProcessedAt (DateTime?, опциональное) — дата и время обработки брони.
- SeatsCount - число мест для бронирования

## Управление схемой базы данных
Схема базы данных управляется с помощью миграций EF Core. Это означает, что любые изменения в моделях автоматически генерируют скрипты для обновления структуры БД — как в разработке, так и в продакшене.

### Команды для работы с миграциями
Выполняйте команды в консоли Package Manager (PMC) или через .NET CLI в корне сервиса.

**Через PMC:**

1. Создать новую миграцию:

```
   Add-Migration InitialCreate

```
2. Применить миграцию к базе данных:

```
   Update-Database
```

## Авторизуйтесь в Swagger UI
Скопируйте значение accessToken.
Нажмите кнопку Authorize 🔒 в правом верхнем углу.
В поле Value вставьте токен без слова Bearer:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Нажмите Authorize → Close.
Swagger автоматически добавит заголовок Authorization: Bearer <token>
ко всем последующим запросам.
